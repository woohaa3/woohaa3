Selection exposes Edit in the top action bar. Explicit Free movement enables WASD/Z/X/mouse control; Esc or lock loss returns to composition with the draft preserved. `web/services/canvas-service/src/world-authoring/capture-producer.ts` compiles pinned scripts or parses pinned GLB assets (including embedded textures), then renders through `woohaa-world-renderer-protocol-v1`. Shared-world framing capture is page-driven: the host observes canonical camera/world changes and lists pending captures, the browser renders the camera inside the same Bevy app (`client/bevy/src/world_capture`, excluding the isometric grid) and commits the PNG, and the host verifies the framing is still current, saves it through trusted Media and freezes. `task/run-service.ts` freezes directly connected cameras as actual Provider image references; same-camera explicit selections are deduplicated. Scene-area presentation: Render Scene v38 projects canonical scene-area bounds independently of card geometry; `app/scene3d.rs` draws their ground outlines and `canvas-shell/interaction-2d-input.ts` cycles overlapping areas using the renderer ground query. `world-scopes/plugin.tsx` mounts only `scene-area-timeline.tsx` for a singly selected animated director, above its open execution dock or outside its ground title; the two former replay entries are removed. `canvas-runtime/world-animation-transport.ts` owns page-local play/pause/seek/loop state with independent remembered playheads, pauses on selection changes, and resets changed/deleted animations or pages. Spatial lease storage: `web/services/canvas-service/src/storage/sqlite/spatial-leases.ts` persists typed locks, request intent and execution state; conflicts identify the target and occupying run/epoch. Kind-typed member identities, transform/camera codecs, forward/inverse commands, receipt sources, history snapshots and the versioned scene-area occupancy view are validated before the UI can consume them.

Scene-area prepare occupancy: `scene-area-service.prepare` attaches `WorldScopeOccupancySnapshot` (`world-scope-occupancy-v1`) read from the durable SQLite spatial lease locks for exactly the classified writable/read-only objects. `idle` requires a successful store read with no in-scope lock; `occupied` carries each kind-namespaced target with `runId`/`epoch`/`active|cancelled`; `unknown` covers a missing/unreadable store or a legacy response without the field. Cancelled runs keep their locks until trusted stop confirmation, reopen keeps them visible, and the view never creates a run/lock/capability or replaces the commit-time gate. Additions are documented here and covered by `web/services/canvas-service/src/world-authoring/scene-area-occupancy.test.ts` and `web/tooling/shared-world-scopes-http.test.ts`.

Canvas model synchronization detects bridge payload snapshot changes independently of scene flags, so delayed or released payloads rebuild world roots. Bridge ingestion and model lease reconciliation run on the host thread; native desktop also confines its schedules there.

Group appearance: `web/contracts/src/canvas/group-appearance.ts` owns the shared definition and read-only default for ordinary groups. It returns a side-effect free failure before command construction, so a dragged member cannot expand its own drop target. During an ordinary node drag, the same frozen center rule publishes a render-only target id; Bevy accents the target group frame/fill and clears it on release or cancellation. Existing enlarged groups do not shrink automatically; users may tighten them with the resize handle. Group bodies remain closed rounded rectangles with 12-unit corners. The badge is the group model itself: `web/contracts/src/canvas/group-badge.ts` and `bevy/src/canvas_query/group_model.rs` share one derivation — the anchor is the structural bottom midpoint plus 40 canvas units (`GROUP_BADGE_ANCHOR_OFFSET`); both ordinary and film-set groups use the shared canvas model unit (`placement.scale * CANVAS_UNITS_PER_METER`, the absolute metric form identical to a `model3d` card): badge size comes only from the model geometry and placement, never from the group rectangle or badge rect. An ordinary group centers its projected AABB on the anchor; a film-set group anchors the projection's top edge at that point with `group.badgeTopAnchor`, so the scene grows only downward and never covers member cards. There is no fixed frame, no presentation multiplier and no `fit` clamp, so a large model is never cropped; without a prepared model there is no badge rect and no placeholder. `frame_path`, `outline` and `fill_regions` are the same closed rounded rectangle; `badge_path` is only the projected badge polygon used for picking and for collapsed outlines. Single groups reuse Rust resize drawing/picking and existing gestures on the structural corners; minimum dimensions include members and the 80-unit footer. `bevy/src/canvas2d/group_surface.rs` was removed with the badge tail. Every group draws a per-group translucent 2D panel entity (`canvasNodeSurface` at the shared 0.55 fill alpha) whose transform z participates in Transparent2d ordering in `canvas2d/group.rs`, so ungrouped roots occupy the lowest render layer, group roots sort by id, and parent-first members cover their own group. There is no 3D group surface or badge plate, so the 3D camera simply renders the models above the grid and the 2D panel never double-stacks with a 3D underlay. Depth direction is a hard constraint: `OrthographicProjection::default_2d` swaps near/far and the 2D pipelines compare depth with `GreaterEqual` against a buffer cleared to 0.0, so a larger world z renders in front; `draw_order::render_z` must stay monotonically increasing in slot (`10.0 + slot * 0.1`), matching cards, action bars and marquee. A descending mapping drops group panels behind ungrouped nodes. Surfaces stay on layer 0 and out of capture/focus, reuse meshes for movement/viewport changes, and release/rebuild them on size or collapsed-state changes. Point picking, spatial bounds, residency, demand and running culling cover the projected badge extent below the structural rectangle. Marquee, resize and navigation retain rectangular structural dimensions without that extent. `model3d/layout.rs` consumes the shared model layout; Render Scene v34 carries `group.modelBounds` alongside focus-workspace references. Scene references alone do not prove payload preparation or visible rendering. The default groupAppearance now depicts three linked node cards on a shared tray. Scene v34 retains `group.collapsed` for the direction hint. Overview projection removes descendants/edges/actions, incremental positions omit hidden rows, and residency hides member content except explicit focus pins. The scene builder emits a parent-first render sequence with ungrouped roots at the lowest layer and group roots sorted by id, so group surfaces sit below descendants and group-to-group order stays visible. The shared node index caches hidden descendants, drop-eligible groups, and complete working AABBs (including off-screen entries and compact collapsed obstacles) per working identity; bounded queries reuse that index without pointermove/pan/zoom rebuilds. Drag-drop excludes collapsed/hidden containers, transient cleanup removes hidden selections, and navigation/dock reveal use compact bounds.

## Optional native document editor

`desktop/src/document_editor` owns typed admission, bounded asynchronous controls, layout/input generations and retained completion receipts. `desktop/src/editor_runtime.rs` registers optional factories and binds the existing Bevy device on the host thread; the default registry is empty.
