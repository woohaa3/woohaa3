# Client code map

Empty authoring defaults: `web/contracts/src/canvas/agent-node-descriptors.ts` supplies empty model scripts to the menu, MCP and canvas scripts; `animation-snapshot.ts` creates film sets with empty items. `node-dimensions.ts` owns the composite minimum 200×150 (default 260×195), used by explicit command validation, layout and resize. Render Scene v28 carries the optional trusted `emptyPlaceholder` declaration; `web/extensions/film-set/src/preview/browser/model-adapter.ts` enables it only for valid empty film sets. `bevy/src/model3d/empty_placeholder.rs` owns derived plinth geometry and cached extruded 3D side lettering on reserved overview layer 4, excluded from focus, picking, content bounds, previews and exports.

Shared composite children: `web/contracts/src/canvas/composite-children.ts` standardizes container/entity relationships, placement, grouped construction, owner movement and removal. `web/frontend/src/extension-api/composite-assets.ts` owns trusted child declarations, shared rect panels, ownership links and drag-along selection; `bevy/src/canvas_query/composite_panel.rs` and `bevy/src/canvas2d/scope_panel.rs` own geometry, text and thumbnail lifecycle. Film-set objects/shots and the eight-direction workflow use this API. Containers have no DOM overlay. Render Scene v28 is required; extension usage is documented in [COMPOSITE-CHILDREN.md](web/extensions/COMPOSITE-CHILDREN.md).

Film-set object containers: `web/contracts/src/canvas/film-set-object-container.ts` owns deterministic `(filmSetNodeId, itemId)` entrance identities; containers store ownership only. `film-set-object-replacement.ts` copies a model snapshot, preserves object identity/transform, adapts compatible motion bindings and disables incompatible scripts. The reducer creates containers for every object by default and reconciles owner movement, group and deletion; owner `filmSetObjectContainersHidden` persists explicit visibility choices; protected item-set edits restore snapshot and motion together. Sync protocol 6 protects these roles from older normalizers. `web/extensions/film-set/src/authoring/browser/object-containers.tsx` owns single-model drop and feedback; object-container-commands hydrates existing scenes on opening and saves per-object hide/show from the right-hand list through protected edits; its model adapter derives container geometry from the owner's current object. Clipboard remaps owner/item IDs together and double-click opens the owner film set.

Model resource registration: `bevy/src/bridge/assets.rs` retains the whole incoming registration batch until `queue_scene` accepts its references, then evicts idle resources. The 32-entry cache budget must never remove models from a not-yet-accepted first frame; mixed model/card scenes can legitimately exceed it.

Film-set embedded model cards: the reducer maintains a real `model3d` child under each model object container, copies the current item model into its nodeData and derives its size with 12 units of padding on all sides. Canvas selection/copy targets that child; left dragging its header or preview moves the outer container, preserving the child's local position. Reconciliation owns child layout, so `edit-plan.ts` excludes its derived updates from independent edit replay.

Group appearance: `web/contracts/src/canvas/group-appearance.ts` owns the shared definition and read-only default for groups and film sets. The model-scene plugin prepares ordinary groups; the film-set adapter composes its appearance alongside owned items. Residency admits groups and leases their prepared resource keys; groups consume no offscreen preview slot. `web/contracts/src/canvas/domain/core/group-geometry.ts` owns `groupBottomPadding = 80` and `getGroupLayoutSizes`: creation, reparent, refit and script planning reserve the footer; existing documents, nested groups and sizeOverrides share a pure size projection that preserves manually enlarged sizes without moving members or rewriting stored nodes. Node rectangles, selection bounds, captured group rectangles, navigation `nodeWorldRect`, organization/Agent dimensions and `canvas-node-index.groupBounds` consume the same recursive size projection. Drop/reparent freezes group sizes from the working index before applying dragged member previews, passing them to containment and reparent planning so a dragged member cannot expand its own drop target. Existing enlarged groups do not shrink automatically; users may tighten them with the resize handle. Group bodies remain rounded rectangles with a compact embedded bottom badge. `bevy/src/canvas_query/group_model.rs` defines the 1× baseline as an 88×64 canvas-unit badge (adapted for narrow/short groups), 12-unit corners and a 6-unit lower lip. Models fit within the 56×44 baseline and center on the fixed badge center; their aspect ratio never changes its silhouette. `frame_path` draws an open dashed group frame between badge joins, `badge_path` draws its solid rim, and `outline` shares the combined outer perimeter for running feedback and point picking. No original bottom edge crosses the badge interior. Single groups reuse Rust resize drawing/picking and existing gestures; minimum dimensions include members and the 80-unit footer. `bevy/src/canvas2d/group_surface.rs` uses the existing 3D main camera for the theme-colored 0.55-alpha group underlay and opaque badge face, above the grid and behind models. The badge covers its own underlay without covering models. Surfaces stay on layer 0 and out of capture/focus, reuse meshes for movement/viewport changes, and release/rebuild them on size or badge-presence changes. Point picking, spatial bounds, residency, demand and running culling cover the actual scaled badge extension (six units below at the default 1×). Marquee, resize and navigation retain rectangular structural dimensions without the lip. `model3d/layout.rs` consumes the shared model layout; Render Scene v32 carries `group.modelBounds` alongside focus-workspace references. Scene references alone do not prove payload preparation or visible rendering. The default groupAppearance now depicts three linked node cards on a shared tray. Strict group-only `nodeData.groupCollapsed` uses existing edit history; `web/contracts/src/canvas/group-presentation.ts` projects a 196×112 compact group at the same bottom-center while preserving structure and expanded size. Rust badge picking returns the existing `group-toggle-collapse` NodeAction; `canvas-shell/input/group-badge-click.ts` accepts a short same-target click and rejects movement, cancellation, read-only and concurrent changes. Scene v32 retains `group.collapsed` for the direction hint. Overview projection removes descendants/edges/actions, incremental positions omit hidden rows, and residency hides member content except explicit focus pins. The shared node index caches hidden descendants and drop-eligible groups per working identity without a full scan on warm release. Drag-drop excludes collapsed/hidden containers, transient cleanup removes hidden selections, and navigation/dock reveal use compact bounds.

Film-set static image references: `web/contracts/src/canvas/film-set-shot-image-reference.ts` owns image profiles, stable version identities and ready asset validation. Sync protocol 5 protects the independent image role; atomic clip conversion and protected undo/replay update consumer roles together. `web/extensions/film-set/src/authoring/browser/shot-image-reference.ts` owns bounded T=0/High capture, PNG registration, reuse/retry and download. Dynamic recording excludes static clips. The inspector owns object-first authoring and saved composition feedback; the shared camera panel takes an explicit capture policy.

`web/frontend/src/cordis/plugins/task-execution/submit-coordinator.ts` freezes image inputs and parameters at click time and resumes each waiting consumer once. The page shares this coordinator with ModelExecutionHost. `web/services/canvas-service/src/task/shot-reference-resolution.ts` validates frozen image metadata and builds an execution-only mapping; run-service revalidates before durable acceptance. `bevy/src/shot_node_preview` and shared `shot_camera` carry each rig's optional backdrop through preview and capture, waiting for real High/GPU readiness before readback.

Bevy WASM builds resolve one shared mode policy in `scripts/lib/bevy-build-mode.mjs`: development (incremental dev profile, no `wasm-opt`) is the default for `dev`, `dev:frontend`, `dev:desktop` and `build:bevy:dev`; `WOOHAA_BEVY_DEV_MODE=performance` or `build:bevy:perf` selects release compilation with `wasm-opt -Oz -g`; production `build`, `build:bevy` and desktop frontend assembly request release explicitly. `build-bevy-wasm.mjs` derives the target directory from `cargo metadata`, follows Cargo's own job defaults, serializes writers of the shared frontend output through a recoverable lock under `.local/locks/`, and only reuses post-processing when mode, inputs and the recorded JS/WASM/d.ts digests all match.

Start at `web/backend/src/composition.ts` for local host composition, `web/frontend/src/main.tsx` for the interface, and `bevy/src/lib.rs` for rendering. Extension discovery follows `extensions.config.json`. Generated API bindings enter this repository only as `api/gen/es` output: a protocol change arrives as a regenerated binding, never as a local edit.

Canvas text raster resolution is shared by the browser WASM and the native canvas: `bevy/src/canvas2d/text_presentation.rs` owns the logical-size metadata, the bounded zoom steps and the glyph cap, and every 2D text producer (labels, edge labels, generation status, drag-attach bar, node action toolbar) only declares logical text. See the rendering map for the scheduling and invalidation rules.

Portable configuration handoff: `scripts/export-config.mjs` reads development configuration through `scripts/lib/development-config.mjs`; `scripts/lib/config-handoff.mjs` owns the separate configuration archive and merge/backup behavior. Tauri `desktop/src/local_host.rs` owns stop/import/restart and delegates `--import-config` to `scripts/desktop-host.mjs`. Application extension settings use the service's config-store API; imported model/deployment files belong to the user data directory.

Runtime model handoff reads the host public snapshot through `scripts/lib/runtime-models-export.mjs`. Imported metadata is displayed through `web/backend/src/host/core/runtime-model-catalog.ts`; it does not register generation providers. Desktop data owns `config/runtime-models.json`.

Windows dependency bootstrap: root `setup.ps1` checks the native toolchain before frozen client/web/api dependency installs; `-CheckOnly` performs only preflight checks. It does not build WASM or desktop installers.

Optional desktop runtimes: `web/runtime-components/` owns locked, signed component downloads, local CLI selection, installation receipts and leases. `web/backend/src/runtime-components/http.ts` exposes the loopback-only management API; the settings plugin provides explicit installation controls. `scripts/package-runtime-components.mjs` builds self-hosted CDN artifacts; `desktop/runtime-downloads.json` and `desktop/runtime-components.lock.json` define defaults and compatibility. Desktop recording watches verified component readiness; model rendering and Agent transports resolve components lazily. See `desktop/RUNTIMES.md`.

Image editing is provided by an installed extension through the extension SDK. The host owns generic focus presentation, camera/texture ports, navigation, edit completion receipts and owner-scoped media-format registration. Editor engines, document formats and runtime assets are outside the host.

Local tool setup lives in `web/extensions/local-agent/src/frontend/settings-panel.tsx`: missing tools expose installation actions, including the shared runtime settings for Codex. `src/backend/runtime-executable.ts` bridges managed Codex and local executables; `process-manager.ts` holds the managed executable lease until process exit. Discovery stays read-only.

Assistant entry points share `web/frontend/src/cordis/ui/assistant-execution/model-selector.tsx` for selection and the empty-directory configuration action. `web/frontend/src/cordis/plugins/agent-assistant/setup-tooltip.tsx` supplies the corner toolbar's first-connection guidance through the optional `canvas.toolbar-action.tooltip` wrapper; it subscribes to the existing data-space-scoped directory and suppresses guidance during loading, errors, and dialogs.

`web/frontend/src/cordis/plugins/agent-assistant/first-use.ts` observes the same directory from the page plugin and opens the assistant dialog at `page: "add"` on the first successful empty result after canvas readiness. A data-space-scoped localStorage marker respects dismissal across reloads; failures, pending dialogs, scope changes and disposal do not create duplicate or stale prompts.

Runtime release layout: `scripts/lib/runtime-release-layout.mjs` owns platform/App-version directory and CDN URL resolution. `build-desktop.mjs` passes the effective App version into host staging; `package-runtime-components.mjs` writes the same platform/version upload directory and atomic signed catalog. Component/cache identities stay unchanged.

Shared runtime archives: `scripts/lib/runtime-archive.mjs` owns deterministic streaming USTAR/gzip generation. `web/runtime-components/index.mjs` accepts legacy schema 1 release-local archives and schema 2 SHA-256 blobs resolved under the runtime root; signed release catalogs remain platform/App-version scoped.

Image editing is provided by an installed extension through the extension SDK. The host owns generic focus presentation, camera/texture ports, navigation, edit completion receipts and owner-scoped media-format registration. Editor engines, document formats and runtime assets are outside the host.

Composite asset node actions use the shared toolbar target contract. Rust toolbar drawing and interaction accept composite assets and anchor their actions to the scope AABB; viewport and position updates retain the same hit geometry. Film-set object rows expose their container action without requiring a selection.

Assistant source defaults: `web/extensions/local-agent/extension.json` and `web/extensions/sdk-agent/extension.json` declare `site.defaultEnabled: true`; OAuth declares `defaultEnabled: true` in `web/extensions/oauth-agent/src/shared.ts`. The application control plane initializes defaults only when no persisted config exists; explicit disabled settings survive restarts. Directory scanning controls installation, while `extension_site_config.desired_enabled` controls runtime activation.

## 节点实现能力注册

`web/contracts/src/canvas/node-capabilities.ts` 定义渲染相关能力的纯契约；`web/contracts/src/canvas/builtin-node-capabilities.ts` 集中声明内置节点的能力组合。`web/frontend/src/extension-api/node-implementations.ts` 持有页面 scope 内的不可变实现注册表，负责 revision、generation、作用域隔离和幂等注销；模型准备、驻留、场景构建、聚焦、动作与缩放从同一解析结果消费。Render Scene 只携带轻量能力结果，Bevy v28 校验后统一绘制和命中。

Composite focus references: `web/frontend/src/cordis/plugins/canvas-shell/composite-focus-context.ts` projects trusted managed children into wrapping 36px tags at the workspace top. Render Scene v29 retains canonical geometry and carries CSS display rectangles plus existing NodeActions. `bevy/src/canvas_query/focus_context.rs` and `bevy/src/canvas2d/focus_reference.rs` draw only a type glyph, one 13px name, and an enabled close control. Rust shares close geometry between drawing and picking; the shell checks per-child `closable` opt-in, ownership/write/history before routing to `CompositeAssetAdapter.closeChild`. Other reference gestures remain inert. Object links start at each object’s top-center bounds; shot links use the source camera’s world position, both projected through the observer at 0.2 opacity. Focus tags have no thumbnail/preview allocation. Each film set exposes at most six objects. Only object containers opt into closing; shots always remain externally visible and have no visibility control. Legacy shot-hidden settings are ignored and removed from pasted film-set data.

Group badge resizing: `web/contracts/src/canvas/group-badge.ts` and Rust group_model share a center-anchored proportional badge rectangle. Optional group-only `nodeData.groupBadgeScale` (0.5–2.5, default 1) changes presentation without changing group size or model identity. Scene v29 carries badgeScale/badgeResizable; `canvas-shell/input/group-badge-resize.ts` consumes the existing `group-resize-badge` NodeAction, previews in gesture state and saves once through edit history. Cancellation/readonly/concurrent changes restore canonical size. Scaled surface geometry, hit/spatial/position increments, residency and demand use the actual extended footprint; prepared model resources remain shared.

AI capability center: `web/frontend/src/cordis/plugins/agent-assistant/assistant.tsx` owns the overview/local Agent/MCP/service-source/diagnostics sidebar and detail drawers. `service-directory.ts` shares the source read model; `capability-pages.tsx` projects actual statuses and canvas conversation history. Source and Provider forms retain drafts and scoped portals while hidden; Provider saves refresh the same directory. MCP installation uses per-target status tables and reports configuration evidence separately from client connectivity.

App-owned extension surfaces: `web/frontend/src/cordis/services/persistent-surfaces.tsx` retains stable DOM/React roots and extension-owned resources across page transitions. Revocable page layout bindings never move the canvas. The extension reconciler revokes normal work on inactive state; optional local recovery owners survive only for settling existing drafts. Identity namespace changes isolate previous owners. Public types are exported through extension-api. App teardown runs on pagehide so cancelling beforeunload preserves resources.

Captured editor viewports: `bevy/src/canvas2d/alpha_checker.rs` skips the host media checker when image focus carries `documentView`. Those frames own document transparency; their outside margins stay transparent to the real canvas. Plain media focus retains the generic checker. Editor packages, assets and build lifecycle belong to independently installed extensions.

Prebuilt extensions: `extensions/photocraft` bundles the image editor runtime and licenses, enabled by default in a standalone checkout. The generic package builder skips packages without build scripts; browser builds verify and reuse prebuilt artifacts, and release assembly includes them without requiring frontend sources. Editor authoring and compilation take place outside this checkout.
