# Service connection authority

`registry.ts` owns durable source metadata and consumer bindings. It is separate from Agent native sessions, Task execution and tool grants. The public contract is `contracts/src/extension/host/service-connection.ts`; read views contain neither secrets nor internal secret pointers. `isServiceConnectionSave` rejects caller-supplied owner, scope, capabilities and credential references. An actor is constructed by trusted host code, never from a request body.

A save reserves a persistent owner/scope/operation identity, stages an immutable encrypted secret version, then atomically publishes the source and operation result with document CAS. Pending operations remain retryable after a crash. Until publication the old source stays authoritative. Replaying a published operation returns the original result; reusing it for different content conflicts. Failed CAS does not clear or replace the old secret. Secret reclamation must only remove unreachable versions during maintenance; old versions must never become an implicit fallback.

Resolution checks owner/scope, the host-fixed consuming extension, binding, purpose, frozen revisions, adapter evidence, model and actual endpoint before reading any secret. An adapter must still use the existing guarded transport (DNS/dial pinning and no credential-forwarding redirects); metadata endpoint validation does not replace that network boundary. No consumer is automatically authorized by having the same URL or model name. Capability publication rejects late versions. Removal tombstones the source, invalidates its versions and retains bindings for explicit repair/history.

Application composition can own the document facade in its durable SQLite store. Backend explicitly injects its isolated encrypted secret facade and deployment target policy. The backend now registers SDK, OAuth and configured site Provider adapters through the fixed extension facade. Each adapter projects its original encrypted authority into the registry without copying a secret; consumers must register protocol/purpose evidence and resolve a frozen revision. Provider factories receive a source-scoped guarded transport, while site-only legacy Providers keep their original opaque handle. UI management and HTTP routes use the same directory; personal Provider binding and administrator-only shared discussion are explicit operations.

## Legacy credential publication

`agent-connections` now also stages immutable secret versions before publishing a metadata pointer. Missing pointers resolve only the original connection/purpose key; an explicit null means revoked and never falls back. Every secret read first verifies live owner-scoped metadata. Clearing/removing publishes invalidation before deleting the active material. SDK configuration reserves an owner-scoped operation and atomically publishes endpoint and secret pointer, without looking up another account by URL.

This is a storage format change. Do not downgrade to a binary that ignores `credentialKeys`: it would read an obsolete legacy key. During a future maintenance rollback, stop writes and work admission, recover pending operations, and restore the **currently published** reference (or its explicit revocation) into the old authority before changing binaries. New records and tombstones must also be mapped. Restoring a database backup alone may revive revoked credentials and is not a supported rollback. The cross-source migration mapping and merge/rollback tooling remain tasks in the change; no migration is claimed here.
