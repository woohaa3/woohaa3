# Runtime components

This dependency-free infrastructure package is shared by the desktop and web hosts. Inspecting or resolving never downloads; the first explicit connection preflight or install action starts preparation. Configure `WOOHAA3_RUNTIME_DATA_DIR`, `WOOHAA3_RUNTIME_DEFAULTS_FILE`, and `WOOHAA3_RUNTIME_LOCK_FILE` before calling the singleton accessor. Registry installs additionally read `WOOHAA3_RUNTIME_NPM_LOCK_FILE`, `WOOHAA3_RUNTIME_TOOLS_DIR`, optional `WOOHAA3_RUNTIME_REGISTRY`, and `WOOHAA3_RUNTIME_INSTALL=disabled` to turn the deployment boundary into an explicit unavailable state.

The immutable App lock pins archive versions and protocols. Claude `localVersions` declares exact compatible CLI versions independently of archive/package versions: Claude SDK `0.3.301` embeds Claude Code `2.1.301`, so these are intentionally different. A Claude local selection without `localVersions` is rejected. Codex local programs are accepted when they identify as Codex and report a version; `blockedVersions` rejects specific CLI versions. A macOS `.app` path is resolved to the bundled Codex executable before that probe. A packaged App is launched by Finder with the launchd PATH only, which has neither version-manager directories nor `node`: discovery therefore also searches user-level install locations and `ChatGPT.app`, and a `#!/usr/bin/env node` launcher is resolved in place to the vendored native binary of the same npm package. When no vendored binary exists the launcher is kept and the `--version` probe reports the real cause; it is never silently replaced by a different installation. Probes require the expected CLI identity and bounded output, in a separate home directory without inherited authentication environment variables. This is a compatibility probe, not a sandbox for arbitrary selected executables.

Defaults contain `trustKeys` (Ed25519 public PEMs). User configuration can override CDN/selected executable paths and append explicit `additionalTrustKeys`, but cannot replace the defaults' trust roots. Catalog signatures cover the exact JSON bytes. Archives must be USTAR `.tar.gz` files with regular files and directories only; links/PAX records, Windows device/stream aliases and traversal are rejected. URLs stay within the configured CDN root; HTTP is supported only for local testing.

Activation occurs only after archive SHA-256 verification and extraction limits. The cache retains signed catalog bytes and checks its receipt against that catalog offline. Every resolution also verifies the entry's persisted SHA-256 and containment; inspection does not reread large binary contents. This detects corrupted entry files; the cache is not a security boundary against a local user able to rewrite App data/trust configuration. Downloaded package dependencies are not individually rehashed on every task.

Publishers must preserve native platform code signatures and perform their normal Apple notarization/Windows release checks before publishing artifacts. The manager never strips signatures or removes quarantine. It verifies distribution metadata and executable permissions; it does not claim to replace Gatekeeper, Authenticode or the consumer's runtime protocol handshake. Managed executable launchers must use the adapter's existing isolated environment and protocol checks.

Cross-process consumers acquire a lease by creating `.leases/<pid>-<uuid>.json` with `{ "pid": 123 }` inside the installation, then **revalidate the entry/ready record after creating the lease**. Do not recursively recreate a missing installation directory to acquire a lease. Release the file after the child has exited. When live external leases exist, removal first writes `.release-requested` and waits up to 1.5 seconds for idle native consumers to stop and release their leases. Busy consumers keep running and removal returns `COMPONENT_BUSY`, clearing the marker. The native watcher must not restart while this marker exists. Removal then renames the installation out of its public location and checks leases again, restoring it if a newly acquired live consumer exists. This ordering prevents acquisition during deletion. A crashed consumer's dead PID lease can be removed automatically. PID reuse is conservative: removal may refuse until that process exits.

`ready.json` contains `schemaVersion`, absolute `entry`, `version`, and `kind`. Non-Node consumers must validate its locked version and entry containment; it is a cache coordination record, not a signed public manifest.

Run `node --test index.test.mjs` to verify downloads, signatures, corrupt/traversing archives, offline caches, cancellation, resume, local CLI selection and leases.

桌面发行构建可用 `WOOHAA_RUNTIME_CDN_BASE_URL` 指定 runtime CDN 根地址；打包将 `<平台>/<实际App版本>/` 追加后写入随包 `runtime-downloads.json` 的 `cdn.baseUrl`，不修改源码中的默认下载配置或信任公钥。独立客户端的部署域名由构建环境提供。

## npm registry source

`source: "npm-registry"` installs the fixed Agent engines from the app-published `runtime-npm-lock.json` instead of a signed archive. The lock carries exact `name@version` identities, sha512 integrity, platform `os`/`cpu`/`libc` constraints, dependency edges, entry rules and the audited lifecycle-script policy. The manager never resolves semver, reads dist-tags, runs `npx`, or installs packages outside that lock.

- Tarballs are fetched from `<registry>/<name>/-/<basename>-<version>.tgz`, verified against the lock integrity and cached in `<data>/cache/npm/`. The registry is deployment-managed (official registry or an enterprise mirror); there is no user-facing registry input.
- Before downloading, the manager probes the locked root tarball with a `HEAD` request against the primary registry and every configured mirror, then starts from the fastest TTFB. The probe is advisory: all probes failing keeps the configured order, and any download failure, HTTP error, timeout or integrity mismatch falls through to the next registry. `/-/ping` is not used because a mirror may serve metadata while its tarball CDN lives on another host or answers with a redirect.
- The shipped lock currently lists `registry.npmjs.org` plus Huawei Cloud and Tencent Cloud mirrors. A deployment can replace that mirror list with `registry.mirrors` in `runtime-downloads.json`; an empty array disables probing and mirror fallback. Setting `registry.baseUrl` (or the Web host's `WOOHAA_WEB_HOST_RUNTIME_REGISTRY`) makes that deployment registry the only source unless `registry.mirrors` is also provided, preserving the previous single-registry override semantics. Probe and per-tarball download timeouts are respectively `probeTimeoutMs` (default 2s) and `downloadTimeoutMs` (default 120s).
- Packages are laid out in npm-compatible `node_modules` (hoist the first version, nest conflicting versions under the requester). After extraction the manager re-reads every package manifest, verifies every dependency edge resolves to the locked version, checks non-optional peers, and probes the entry (`entry.mjs` for dsh, the absolute platform executable for Claude/Codex).
- Only lifecycle scripts in the lock allowlist run, and only as `node <script>` with the app's own Node and a PATH limited to the app tools directory. Denied scripts are recorded and never executed; an unapproved script fails the build-time audit.
- Installation uses a random staging directory, a `ready.json` marker and an atomic rename. Verified tarballs stay in `<data>/cache/npm/` so retries and repairs never redownload them (dsh's 624 packages compress to roughly 1.4 GB; the expanded runtime is 300-900 MB per engine depending on platform). Cancel/interrupt/integrity/space failures leave the previous ready version untouched. `ready.json` stores the absolute entry; the receipt stores the lock digest, entry SHA-256, package count and executed scripts.
- Leases, single-flight jobs and removal semantics are shared with the CDN source. Corrupted cache entries are reported as `INVALID_CACHE` and can be repaired by reinstalling; old versions are retained for rollback.

`probeNpmToolchain` verifies the app-local npm CLI (`<tools>/npm/bin/npm-cli.js`) with the app's Node before installing; a missing CLI reports `NPM_TOOLCHAIN_MISSING` instead of falling back to a user PATH.
